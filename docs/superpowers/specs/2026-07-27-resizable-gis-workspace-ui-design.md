# WebGIS 工作台展示与拖拽布局优化设计

日期：2026-07-27

## 目标与边界

本次改动只优化信息展示和布局交互，不改变路线生成、地图图层、数据加载、路线对比、分析与导出等业务功能。

目标：

- 提升左侧选型区的信息层级与可读性，减少当前窄栏产生的横向滚动。
- 让地图保持主视觉，同时允许用户按工作需要调整左侧栏宽度。
- 让候选方案底栏和左侧控制点区支持鼠标拖拽调整高度。
- 拖动过程顺滑、边界明确，并支持键盘操作、双击恢复默认值和刷新后保留尺寸。
- 在小屏设备上自动回到纵向流式布局，不强行保留桌面拖拽交互。

## 现状

桌面端工作区使用 CSS Grid：

- 顶栏高度 64px。
- 1280×720 视口下左侧栏实际宽度 300px，地图宽度约 944px。
- 左侧栏内部由选型表单和控制点面板上下组成，当前高度约为 450px / 170px。
- 生成候选路线后，地图下方出现候选方案抽屉，使用固定比例占据底部空间。

当前主要问题：

- 300px 左栏承载四列表格、按钮和长文本，容易出现横向滚动，读取与编辑都拥挤。
- 工作区尺寸完全由固定 CSS 决定，无法适应“编辑控制点”“看地图”“比较路线”等不同任务。
- 面板标题、说明、数据源和操作区视觉权重相近，扫描路径不够清晰。
- 拖拽目标尚不存在，用户无法快速放大当前关心的信息区域。

## 方案比较

### 方案 A：只调整固定尺寸与样式

将左栏改为更宽的固定值，压缩文字和间距。实现最简单，但不同屏幕与工作任务下仍无法自适应，也不能满足拖动缩放要求。

### 方案 B：使用浏览器原生 `resize`

给面板增加 `resize: horizontal/vertical`。代码少，但拖动把手位置不醒目、样式与键盘无障碍能力有限，多个嵌套面板也难以保持 Grid 布局稳定。

### 方案 C：受控分隔条与 CSS 变量（采用）

在工作区主栅格和上下区域之间加入明确的分隔条，由 React 管理尺寸，CSS 变量负责布局。该方案能统一鼠标、触摸板、键盘和双击恢复默认值，尺寸可持久化，并能对最小/最大尺寸做可靠限制。

## 布局设计

### 桌面主布局

- 左侧栏默认宽度由 300/320px 调整为 380px。
- 左侧栏允许在 320px 到 520px 之间拖动；同时至少为地图保留 520px。
- 左侧栏与地图之间使用 8px 可操作分隔带，其中视觉线保持 1px，悬停和拖动时使用品牌绿色高亮。
- 主栅格间距从 12px 调整为 10px，避免分隔条叠加后浪费空间。

### 左侧栏内部

- 选型面板和“当前路线控制点”之间增加水平分隔条。
- 控制点面板默认高度 190px，可在 140px 到左栏可用高度的 55% 之间调整。
- 拖动时调整底部控制点面板高度，顶部选型面板自动占用剩余空间。

### 候选方案底栏

- 仅在候选路线存在时显示地图与底栏之间的水平分隔条。
- 底栏默认高度 240px，可在 180px 到工作区可用高度的 55% 之间调整。
- 候选卡片保持横向网格布局；底栏放大时提供更多纵向信息空间，缩小时保持关键指标与操作可见。

### 移动端

- 820px 以下继续使用单列流式布局。
- 隐藏所有拖拽分隔条，清除桌面尺寸变量对布局的影响。
- 地图、候选区和左侧内容按现有顺序自然滚动，避免触摸滚动与拖动手势冲突。

## 信息展示优化

- 左侧面板采用更宽的默认值，四列控制点表格获得可读宽度并消除常规桌面视口下的横向滚动。
- 标题区缩短说明文本的视觉占比，保持标题、说明、步骤标题三级层级。
- 数据源卡片改为紧凑的横向摘要：名称、状态与数据规模按主次排列。
- 表单分组使用轻背景、细边框和更一致的 8/12/16px 间距体系。
- 主要操作按钮保持高对比，次要操作降低视觉重量；禁用状态仍清晰但不抢占注意力。
- 地图工具栏和状态标签保持现有功能，仅优化留白、阴影和边界，使地图内容优先。
- 分隔条增加可发现的点状/短线把手、对应方向光标和拖动反馈。

## 组件与状态

新增一个通用 `ResizeHandle` 组件：

- `orientation`: `vertical` 或 `horizontal`。
- `ariaLabel`: 描述调整对象。
- `onResize(delta)`: 将指针位移传给布局状态。
- `onReset()`: 双击恢复默认值。
- 使用 `role="separator"`、`aria-orientation`、`aria-valuemin/max/now`。
- 支持方向键微调；按住 Shift 时使用更大的调整步长。

新增布局尺寸管理逻辑：

- 主侧栏宽度、左栏底部面板高度、候选底栏高度分别独立管理。
- 初始值优先读取 `localStorage`，无有效值时使用默认值。
- 所有值在应用前进行范围钳制，窗口缩小时不会把地图或面板挤出可用区。
- 只存储数字尺寸，不存储业务数据。

## 错误与降级

- `localStorage` 不可用或内容无效时静默回退到默认尺寸。
- 指针拖动被取消或窗口失焦时立即结束拖动状态，不影响业务操作。
- 不支持 Pointer Events 的环境仍可通过键盘调整分隔条。
- `prefers-reduced-motion` 下不使用尺寸过渡动画。

## 测试与验证

自动化测试覆盖：

- 尺寸读取、钳制和持久化。
- 分隔条方向键调整与双击复位。
- 候选路线出现前后，底栏与分隔条的条件渲染。
- 原有业务按钮、模式切换和路线生成接口保持不变。

浏览器验证覆盖：

- 1280×720 和更宽桌面视口的默认布局。
- 左侧栏向两侧拖动时地图与面板同步变化且不溢出。
- 左栏上下分隔条和候选底栏分隔条可拖动、可复位。
- 刷新后尺寸保留。
- 820px 以下单列布局无分隔条、无横向页面滚动。
