# 删除已生成路线设计

## 目标

在候选路线卡片中增加清晰、安全的单条删除入口。删除只影响当前页面内的生成结果，不改动控制点输入、路网数据或预设方案，用户仍可用原控制点重新生成路线。

## 方案选择

考虑过三种交互：

1. **页面内确认后立即删除（采用）**：卡片内提供“删除”按钮，使用与工作台视觉一致的轻量确认浮层防止误触。状态明确，也不会像浏览器原生确认框那样阻塞页面渲染。
2. **删除后提供撤销 Toast**：操作更顺滑，但需要新增通知状态、计时器与恢复快照，超出本次最小需求。
3. **移动到回收站**：适合持久化路线库，但当前路线仅存在于浏览器会话中，不值得引入额外管理界面。

## 交互设计

- 删除入口位于每张候选路线卡片的操作区，与“加入对比”“进入分析”并列。
- 按钮使用低干扰的危险操作样式，文字为“删除”，并带包含路线名称的无障碍标签。
- 点击后显示页面内确认浮层，明确展示路线名称、影响范围和“删除后可使用原控制点重新生成”。
- 浮层提供“取消”和红色主操作“确认删除”，确认按钮获得默认键盘焦点。
- 取消确认不改变任何状态。
- 确认后立即从候选路线列表和地图中移除该路线。

## 状态同步

删除路线时同步完成以下处理：

- 从 `routes` 中移除目标路线。
- 从 `comparedRouteIds` 中移除目标 ID。
- 如果删除的是当前活动路线，将第一条剩余路线设为活动路线；没有剩余路线时清空活动路线。
- 保留 `manualRoutePlans` 和控制点输入，便于重新生成。
- 更新生成状态，明确提示路线已删除以及可以重新生成。
- 删除最后一条路线后，候选路线底栏按现有逻辑自动收起，地图回到无候选结果状态。

## 代码边界

- `src/domain/routeCollection.ts`：新增纯函数，统一计算删除后的路线、活动路线和对比状态。
- `src/components/CandidateRouteDrawer.tsx`：只负责展示删除按钮并上报目标路线 ID。
- `src/components/RouteDeleteDialog.tsx`：负责无障碍确认浮层和恢复说明。
- `src/App.tsx`：负责确认、调用纯函数更新 React 状态以及更新提示文案。
- `src/styles.css`：增加删除按钮的常态、悬停和键盘焦点视觉反馈。

## 测试与验收

- 纯函数测试：删除普通路线、删除活动路线、删除最后一条路线、清理对比 ID。
- 组件测试：候选卡片渲染包含路线名称的删除按钮。
- 应用测试：确认删除入口由应用传入，并保持初始无路线页面不显示候选抽屉。
- 浏览器验收：生成路线、取消删除、确认删除、地图同步消失、底栏收起、重新生成可用。
- 完整测试与生产构建均须通过。

## 非目标

- 不增加路线持久化、回收站、批量删除或撤销通知。
- 不删除用户输入的控制点或预设路线方案。
- 不改变路线生成、评分、分析和导出算法。
