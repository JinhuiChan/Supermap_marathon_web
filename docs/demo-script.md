# 比赛演示脚本（3-5 分钟）

## 演示准备

1. 确认 iServer 可访问：`http://127.0.0.1:8090/iserver/`
2. 启动前端：`npm.cmd run dev`
3. 打开：`http://127.0.0.1:5173/`
4. 建议浏览器全屏，先滚动确认右侧“图层控制”“路线研判”“成果导出”都能看到。

## 第一幕：系统总览（30 秒）

**讲法：**  
这是一个基于 SuperMap WebGIS 的武汉马拉松赛道智能选线系统。左侧是候选赛道库和单路线指标，中间是真实 SuperMap iServer WMS 地图，右侧是服务接入、图层控制、路线研判、多路线对比和成果导出。

**操作：**
- 指向右侧 SuperMap 接入面板，说明 iServer 和 WMS 底图均已连接。
- 指向地图中的路线和服务点，说明底图来自 iServer，路线和点位是前端业务图层。

## 第二幕：路线与服务点可视化（45 秒）

**讲法：**  
系统内置三条候选路线，并将起终点、补给、医疗、停车等赛事保障点叠加到真实地图上，方便规划人员同时判断路线条件和保障能力。

**操作：**
- 在左侧切换“东湖绿道景观线”“城市核心保障线”。
- 在右侧“图层控制”中关闭和打开“赛事服务点”，展示服务点图层可控。
- 鼠标悬停服务点，展示点位名称、类型和服务等级。

## 第三幕：单路线研判（60 秒）

**讲法：**  
系统把 DEM、路线形态和服务点数据转成四个评估维度：地形友好度、通行组织、赛事保障、观赛体验。这样评委可以看到推荐结果不是单纯排序，而是有指标依据。

**操作：**
- 选中“两江四岸平缓线”。
- 指出“路线研判”中的推荐理由和风险提示。
- 说明补给覆盖、医疗间距、坡度和遮荫覆盖等指标如何影响推荐。

## 第四幕：多路线对比（60 秒）

**讲法：**  
勾选多条路线后，系统会自动计算难度分、保障分和综合推荐分，并输出推荐排序。

**操作：**
- 勾选三条路线加入对比。
- 展示右侧“多路线对比”表格、柱状图和坡度剖面对比。
- 强调推荐方案可用于后续现场踏勘和交通组织深化。

## 第五幕：SuperMap 技术栈（45 秒）

**讲法：**  
本项目使用 SuperMap iDesktopX 处理武汉 DEM 和赛道矢量数据，通过 SuperMap iServer 发布 WMS 地图服务，前端加载真实地图服务并叠加业务分析图层，形成从 GIS 数据处理到 WebGIS 决策展示的闭环。

**操作：**
- 指出 SuperMap 接入面板中的 iServer 地址、WMS 底图源、DEM 元数据。
- 说明数据包可下载，便于复查和扩展。

## 第六幕：成果导出（30 秒）

**讲法：**  
分析结果可以导出为文本报告，包含 SuperMap 服务依据、路线排序、推荐理由和风险提示，便于组委会存档或二次汇报。

**操作：**
- 滚动到“成果导出”。
- 展示报告预览。
- 点击“导出对比报告”。

## 收尾总结（20 秒）

**讲法：**  
这个系统完成了“数据导入、服务发布、地图展示、路线评价、对比推荐、成果导出”的完整链路。后续可以继续接入交通管制、实时人流、医疗资源和三维场景服务，把方案从赛道初选推进到赛事运行指挥。

## 备用方案

- 如果 iServer 或 WMS 未启动，前端会降级到 SVG 示意图，不影响核心对比演示。
- 如果三维服务暂未发布，三维面板会显示待发布状态，不影响二维分析闭环。
- 如果网络不稳定，先确认本机 `127.0.0.1:8090` 和 `127.0.0.1:5173` 可访问。
